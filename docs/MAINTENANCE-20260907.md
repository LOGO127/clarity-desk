# 2026-09-07 维护记录：转写重复请求

本轮以 `fc92adb` 为基线，选择一个可复现的问题修复，版本为 v0.3.1 公开测试版。没有新增依赖，没有改变飞书公式识别、更新请求或录音采集流程。

## 问题与修复

原录音记录页仅保存一个正在转写的会话 ID：同时开始 A、B 后，A 可能提前恢复可点击；切换页面返回也会丢失页面内的忙碌状态。主进程的会话磁盘锁只会串行执行请求，不会合并重复工作。第一项成功并清理断点后，排队的重复请求可能再次上传全部混音切片，产生额外费用。

主进程现在在读取凭据、等待会话磁盘锁之前登记运行中的任务，同一会话的并发请求共享这一任务。界面改用会话 ID 集合，一项完成只解除自身按钮状态。任务在成功或失败后清理，允许后续主动重试；不是永久结果缓存，也不承诺跨重启去重。页面状态只是交互反馈，主进程才是去重保障。

另包含此前已合并的桌面测试启动等待修正（PR #11）：只有实际应用页面与主标题就绪，才开始读取应用信息。
